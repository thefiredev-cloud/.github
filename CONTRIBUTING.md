# Contributing

Thanks for your interest. This guide applies to every repository under thefiredev-cloud that does not have its own `CONTRIBUTING.md`.

1. For anything larger than a typo, open an issue first and describe the problem you want to solve. If the repository has issues turned off, open a small pull request with that description instead.
2. Keep each pull request to one change, with a clear title and a short note on how you tested it.
3. Run the checks the repository already uses (its README and CI workflow list them) and make sure they pass.
4. Never include secrets, personal data, hostnames, or private IP addresses in code, tests, logs, or screenshots.

Security problems go through [SECURITY.md](SECURITY.md), not public issues.

By contributing, you agree that your contribution is licensed under the repository's license.
